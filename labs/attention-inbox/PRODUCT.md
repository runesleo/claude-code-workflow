# Product wedge: One Inbox for Agent Attention

## Positioning

**Your agents work everywhere. You only need one inbox.**

The wedge is not another multi-agent framework. It is the boundary between autonomous work and human attention.

## User promise

Agents continue routine work silently. The user is interrupted only when:

1. a concrete human decision is required; or
2. a meaningful risk needs awareness.

Everything else is suppressed or left in history.

## V0 scope

- a portable event contract
- deterministic escalation
- evidence-aware rendering
- duplicate suppression
- adapters for existing agent/task systems

Not V0:

- another canonical task database
- another scheduler
- another orchestration engine

## Public-core boundary

The public layer can include:

- protocol/schema
- local reference logic
- adapters
- basic inbox policy
- synthetic fixtures
- conformance tests

Future product work can focus on reliable delivery, cross-device history, team routing, and observability without changing the event contract.

## Activation metric

Do not optimize for GitHub stars first.

A useful pilot user should satisfy all three in one week:

- connects at least 2 agents/workers;
- receives at least 5 meaningful inbox events;
- completes at least 3 decisions from phone without opening the laptop.

## Differentiation

Coding-agent workspaces optimize how agents work together.

Attention Inbox optimizes when a human must re-enter the loop.
