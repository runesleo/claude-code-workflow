# Leo System AGENTS（公开脱敏示例）

> 这是一份可选的工作规则样例，提炼自真实多 AI 协作经验；不是私人原文，也不会随 QuietHarness 的默认 Core 安装。先按自身规模删减，勿直接覆盖现有 AGENTS.md。

## 目标与原则

- 追求实际结果与可核验证据；系统可用性优先于复杂叙事。
- 先理解用户问题和验收条件，再决定是否写代码。
- 遇到真实的并发冲突后才引入 claim、单 Writer 等协调机制。

## 开工与持续推进

1. 读取项目适用规则、仓库状态、现有实现和未提交改动。保留不相关的用户工作。
2. 从唯一可信的任务记录恢复目标、负责人、上次证据、阻塞和下一动作。缺失时明确报告，不能编造历史。
3. 继续原任务，在原位置记录结果并回读。更换 Agent 不代表重新建任务库、提醒或调度器。
4. 批量完成相邻的安全动作，推进到可验证节点再报告；不必每修改一步就问一次是否继续。
5. 需要分工时，由稳定 Owner 对结果负责，Worker 可替换；同一仓库同时只保留一个写入者，明确交接。单人任务不需要额外仪式。

## 修改与验证

- 限定修改范围，优先小而可逆的补丁。高风险实验先隔离测试，并保留回滚方式。
- 用测试、diff、运行回执或可信来源证明结论；失败、未知和部分完成要如实写明。
- 更新任务状态时附上产物、验证、阻塞及下一门槛，写回后再读取核验。
- 重试任何可能产生外部效果的操作前，先检查是否已执行，避免重复动作。

## 权限与安全

- 在既有授权范围内，可以连续执行只读检查与低风险本地可逆操作。
- 资金、交易、账号、凭证、对外消息、公开发布、删除及生产高风险操作必须另行满足明确批准和已有门禁。
- 不提权、不绕过系统保护、不导出私密凭证。遇到权限边界时说明准确阻塞，不猜测。
- 公开分享时排除个人身份、真实账户、持仓、资金、健康、客户、私有绝对路径、实时任务、会话 ID 和生产控制细节；使用合成示例与相对路径。

## 进化边界

- 只沉淀实际使用且被验证能减少错误的做法，不以规则数量衡量成熟度。
- 保持默认 Core 精简。此扩展示例由读者自行选择，不成为安装依赖。
